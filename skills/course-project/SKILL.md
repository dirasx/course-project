# Курсовая

Скилл для студентов, которые делают инженерную курсовую в Codex. Он помогает составить план по заданию и своему варианту, продолжить работу в новом чате и проверить расчёты, пояснительную записку и чертежи перед сдачей.

[English description](#english)

## Начало и продолжение работы

1. Определи корень текущей курсовой. Прочитай существующий `AGENTS.md`, краткий `STATUS.md` и нужные пункты `PLAN.md`. Открывай материалы конкретной главы по мере необходимости.
2. Для новой курсовой используй [шаблон AGENTS.md](assets/AGENTS.md). В существующей дополни только недостающие правила. Сохрани рабочие пути и действующие инструкции. Исходники нового варианта берутся из файлов, предоставленных пользователем.
3. Создай недостающие записи по схеме ниже. Заполни известное из задания и файлов, затем проверь исходные данные по порядку ниже.

| Где | Что хранить |
|---|---|
| `AGENTS.md` | Постоянные правила и точки входа. |
| `PLAN.md` | ID, ожидаемый результат, статус, зависимости и путь к проверенному результату. |
| `STATUS.md` | Короткий срез: текущий комплект, ближайший шаг, блокеры. Обновляй после существенной работы. |
| `DECISIONS.md` | Принятые решения, ограничения и предпочтения этой курсовой. Для каждого укажи источник, область действия и затронутые материалы. |
| `agent_chapters/<глава>/START.md` | Задание для отдельного исполнителя, только если оно нужно. Включи входные пути, границы записи, критерий готовности и подтверждённый ID главного чата, если используется очередь. |

## Проверка исходников перед вопросами

1. Изучи задание, данные варианта, методичку, образец и текущие материалы. Составь план по разделам с нужными входными данными и зависимостями. Отметь потенциальные пробелы, противоречия и ошибки, которые могут повлиять на расчёт или оформление.
2. По каждому существенному сомнению сначала сверяй первоисточник: страницу, таблицу, примечание, единицы и принадлежность нужному варианту. Сопоставь формулу и подстановку с методичкой и образцом, перепроверь арифметику или перенос данных, если они могли дать расхождение. Исправь подтверждённые ошибки в рабочих материалах. Отдельно отметь, где требуется решение пользователя. Значение из чужого варианта не восполняет пробел в текущем.
3. Выполни доступные независимые пункты. Как только проверка источников исчерпана, задай пользователю одним коротким списком вопросы, от которых действительно зависит следующий шаг. Для каждого укажи, что уже проверено и на что повлияет ответ. Если есть обоснованный вариант решения, предложи его и назови ограничение. Зафиксируй оставшиеся вопросы в плане, ответы — в `DECISIONS.md`. Продолжай работу по пунктам, которым ответы не нужны.

## Работа и приёмка

- Выбери готовый к работе пункт плана. Проверь задание, вариант и текущий файл. Для спорных значений отметь происхождение: дано, принято, вычислено или пока неизвестно. Укажи источник и страницу, единицы и систему отсчёта, если они влияют на результат.
- Храни исходники отдельно от рабочей сборки. Связывай расчёт, таблицу, график и чертёж одним набором данных. Если изменился вход, отметь зависимые результаты и пересобери их перед приёмкой.
- Когда пользователь поручил делегировать, главный запускает доступных субагентов на независимые пункты. Передай каждому ожидаемый результат, нужные файлы и критерий проверки. Долгоживущему чату главы передай `START.md` и текущие пути к файлам. Один исполнитель за раз владеет активным DWG и печатью AutoCAD в общей сессии Windows.
- Перед сдачей открой итоговый PDF записки и проверь изменённые страницы, рисунки, таблицы и оглавление. Статус готовности относится к конкретным проверенным файлам.

## Передача результатов глав

1. Когда глава готова, сохрани её в рабочий файл. В выделенной папке `handoff/` сохрани карточку с номером главы, ID пункта плана, версией результата, путями к файлам, источниками, выполненными проверками, ограничениями и следующим шагом. Укажи пути, по которым главный чат сможет открыть результат и карточку.
2. Если пользователь разрешил передачу в главный чат, его ID известен и очередь доступна, поставь в очередь короткий отчёт с номером главы и путями к результату и карточке. Передай ID и текст как отдельные аргументы. Внутренний субагент может вернуть карточку через штатный канал результата.

   ```sh
   codex queue --thread "<ID главного чата>" --message "Глава <номер> готова. Файл: <путь>. Карточка: <путь>."
   ```

3. Если передача в главный чат не согласована, ID не подтверждён, очередь недоступна или команда не подтвердила постановку в очередь, оставь тот же короткий отчёт в итоговом ответе чата главы. Карточка в `handoff/` доступна главному при следующем просмотре проекта.
4. Главный завершает текущую работу. Отчёт из очереди разбирает на следующем ходу, а при возобновлении проекта проверяет ожидаемые карточки в `handoff/`. Принимает главу после проверки результата и обновляет соответствующий пункт `PLAN.md`. Повторную карточку по уже принятой версии файла достаточно сверить с записью в плане.

## Работа с чертежами

Добавь в `PLAN.md` нужные чертежи и листы по текущему заданию. Для каждого укажи исходники и связанные расчёты, требуемые виды или разрезы, рабочий файл, итоговые форматы и проверки. Используй данные своего варианта для геометрии и требования к оформлению из задания, методички и образца.

Выбери действие по цели задачи. Подключай подходящие скиллы, если они доступны в текущей сессии.

| Задача | Что делать |
|---|---|
| Создать новый чертёж | Собери из задания и расчётов геометрию, единицы, виды, размеры и подписи. Подготовь чертёж доступными CAD-инструментами или оставь в плане спецификацию для черчения, если CAD недоступен. |
| Восстановить чертёж из исходника | Используй `$drawing-redraw`. Выбери исходник, по которому можно подтвердить геометрию, и отметь нужные опорные размеры. |
| Проверить или исправить существующий DWG | Используй `$dwg-review` для проверки исходника, ограничений правки и результата. |
| Проверить листы PDF | Используй `$drawing-pdf-review`. Проверь читаемость, обрезку, размеры, подписи, согласованность видов и ссылки на разрезы. Привяжи замечания к месту на листе. При наличии только PDF отметь проверки геометрии модели, слоёв и внешних ссылок как открытые. |

Для черчения, восстановления, правок и замеров используй уже подключённый AutoCAD MCP, если его инструменты поддерживают нужную операцию. Для File IPC вызывай инструменты последовательно. Если подходящего подключения нет, используй Computer Use при доступе к открытому AutoCAD. Иначе продолжай со спецификацией, расчётами или проверкой предоставленного PDF и скажи, для какой операции ещё нужен доступ к AutoCAD.

Для листов с критичными размерами, углами или отметками сохрани рядом с пунктом плана повторяемые проверки. Для каждой укажи ожидаемое значение, его источник, единицы, допуск из задания или методички, если он задан, и как однозначно найти геометрию для замера. При правке замерь критичные элементы затронутого листа до изменения, если доступен исходный DWG. После сохранения, в том числе после правки подписей, заново открой DWG или считай сохранённый файл поддерживаемым инструментом и повтори замеры. Запиши файл или ревизию, ожидаемое и фактическое значения, отклонение и статус или причину, по которой замер не выполнен. Если допустимость расхождения зависит от неизвестного допуска, оставь её открытой. При выпуске листа проверь свежий PDF печати для той же версии DWG.

## Записка по образцу

- Главный или оформитель перед сборкой сверяет соответствующие страницы образца и рабочей записки. Сохраняй структуру, порядок изложения, стиль формулировок, обозначения и запись формул, подписи, нумерацию и оформление таблиц и рисунков настолько близко к образцу, насколько позволяют требования задания и текущие данные. Подставляй данные своего варианта. При расхождении приоритет у задания и требований преподавателя. Ошибку в формуле или неприменимый метод отметь для проверки перед переносом.
- Следуй принятому в образце способу указывать происхождение формул и данных. Если там есть ссылка, проверь применимость первоисточника и укажи фактический источник. Если ссылок в этом месте нет, сохрани такой стиль, если задание или преподаватель не требуют ссылку. Подробную трассировку сохраняй в рабочих материалах.
- В сдаваемой записке, таблицах, подписях и на листах чертежей не упоминай образец как образец и не вставляй фразы «как в примере» или «по образцу», если пользователь или задание прямо этого не требуют. Описывай расчёт и решения самой курсовой. Ссылки на фактические источники, когда они нужны, сохраняй.

## Как учитывать обратную связь

- Во время работы применяй уточнение пользователя к текущей задаче. Долговременное уточнение о варианте, оформлении или проверках запиши в `DECISIONS.md` по схеме «правило → где действует → источник → что перепроверить». При изменении решения обнови действующую запись и затронутые пункты плана. Сохраняй суть, а не переписку.
- Если пользователь сформулировал правило для следующих курсовых или одинаковое исправление повторилось в нескольких проектах, предложи короткую формулировку для общего скилла. При запросе улучшить скилл перенеси в него подтверждённое правило и проверь на примере, что оно помогает следующему проекту. Данные варианта, имена и пути остаются в документации соответствующей курсовой.

## English

Course Project is a Codex skill for engineering students working on a technical course project. Start with your assignment brief, variant data, and any guidelines or sample report you have.

- **Plan your work.** Break the assignment into chapters and keep the plan, progress, and decisions available across sessions.
- **Check your inputs.** Trace values to the assignment and the correct variant, verify units and calculations, and flag gaps that need your input.
- **Plan and verify drawings.** List the drawings, source calculations, required views, and outputs in the project plan. Keep repeatable checks for critical dimensions and angles. Rerun them against the saved DWG after edits, including annotation changes, and review the current plotted PDF before submission.
- **Hand off completed chapters.** Save the result and a handoff note. Queue a pointer for the main chat's next turn when supported and authorized. If delivery is unavailable, leave the pointer in the chapter chat so the coordinator can pick it up later.

Use `$drawing-redraw` to reconstruct a drawing from source material, `$dwg-review` for an existing DWG, and `$drawing-pdf-review` for plotted sheets. Use each companion skill when it is available. For a new drawing, derive geometry and views from the assignment and the student's calculations.

Use an already configured AutoCAD MCP connection that supports the requested operation. Run File IPC calls sequentially. If no suitable connection is available, use Computer Use with an open AutoCAD session. Without CAD access, continue with a drawing specification, calculations, or PDF review as the task requires. Identify the operations that still need CAD access and mark checks of native geometry, layers, and references as open until the DWG can be inspected.

Open your project in Codex and use `$course-project`. The [project rules template](assets/AGENTS.md) is in Russian.
